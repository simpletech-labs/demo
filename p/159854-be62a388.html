<리스크와 대응>
첫째, 문자 수집은 카드사 정책과 휴대폰 설정에 의존합니다. 아이폰 단축어와 안드로이드 문자 전달 앱은 사용자가 직접 설정해야 하므로, 40명 전원 설정을 돕는 안내문과 설정 확인 화면을 넣고 오픈 첫 주에 설정 완료율을 확인합니다. 둘째, 신한카드 문자 형식이 바뀌면 파서가 깨집니다. 파서 규칙을 코드가 아니라 설정 데이터로 분리해 두고, 인식 실패가 기준치를 넘으면 관리자에게 알립니다. 셋째, 실제 카드 자료는 시험 단계에서 제공되지 않습니다. 형식을 반영한 가상 데이터로 시험하고, 오픈 전 실제 문자 3~5건으로 확인하는 절차를 일정에 넣었습니다.

<기대 결과>
직원은 결제 직후 휴대폰에서 계정과목을 입력하고 잔여 예산을 확인합니다. 관리자는 엑셀 취합 없이 전사 사용률과 위험 부서를 보고, 월말에는 매입 엑셀을 올려 대조만 확인한 뒤 마감합니다. 월 1,000~2,000건 기준으로 담당자의 월말 취합 작업이 사라지는 상태를 목표로 합니다. 완료 기준은 요구사항 정의서의 화면 26개·서버 처리 80종 전 항목 동작, 권한 3종 교차 접근 차단 시험 통과, 문자 인식 성공률 측정값 제출입니다.

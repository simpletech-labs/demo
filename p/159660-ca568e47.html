<프로젝트 진단>
먼저 예산과 공수 이야기를 하는 것이 정직하다고 봅니다. 20만원·5일은 일당 4만원이고, 이 업무는 최소 5일(주소 정제 연동 2일, 분류코드·송장 양식 2일, 예외 처리·테스트 1일)이 필요합니다. 그래서 이 지원서는 두 가지 안을 함께 냅니다. 어느 쪽을 고르셔도 결과물의 경계가 분명하도록 범위를 숫자로 잘랐습니다.

기술적으로 가장 먼저 확인할 것은 CJ 주소 정제·분류코드 API를 어떤 경로로 쓰느냐입니다. 이 기능은 보통 택배 계약(직접 계약 또는 물류 대행사 경유)에 딸린 API로 제공되고, 계약이 없으면 호출 자체가 불가능합니다. 두 번째는 기존 시스템 구조입니다. 관리자 화면에서 이미 자체 송장 양식으로 출력 중이고 운송장번호도 발번해 두었다고 하셨으므로, 새로 만드는 것이 아니라 기존 출력 흐름에 "주소 정제 → 분류코드 조회 → 양식에 삽입" 세 단계를 끼워 넣는 작업입니다. 세 번째는 실패 처리입니다. 주소가 정제되지 않는 건(해외 주소 형식, 오타, 신축 건물)이 반드시 나오므로, 그 건만 사람이 손볼 수 있게 목록으로 빼 주는 설계가 없으면 운영에서 매번 막힙니다.

<작업 범위 — A안 (1,000,000원 / 5일)>
- 주소 정제 연동: 관리자 화면의 수취인 주소를 CJ 주소 정제 API로 호출, 정제 결과(도로명·지번·우편번호·건물번호) 표시 및 수정 저장.
- 분류코드 조회: 정제된 주소로 분류코드(XC37-0 형태) 조회, 주문 건별 저장 및 조회 이력 남기기.
- 송장 양식 인쇄: 기존 자체 양식에 분류코드 인쇄 영역 추가, 발번된 CJ 운송장번호 그대로 사용, 1장·다건 일괄 출력.
- 예외 처리: 정제 실패·분류코드 미조회 건을 "확인 필요" 목록으로 분리, 사유 코드 표시, 수동 수정 후 재조회.
- 운영: 호출 로그·오류 로그, API 키는 서버 환경변수로 보관(화면 노출 금지), 간단한 운영 메모 1장.
- 테스트: 실제 한국 주소 20건(아파트·단독·도로명/지번·오타 포함)으로 정제·분류코드·인쇄 검증.

<작업 범위 — B안 (200,000원 / 1일, 예산 내)>
- 주소 정제 API 호출 함수 1개 + 관리자 화면에서 단일 주소 정제 결과를 확인하는 임시 화면.
- 분류코드 조회·송장 양식 인쇄·예외 목록은 **포함되지 않습니다.** 결과는 "정제가 되는지 확인하는 검증 도구" 수준입니다.

<실행 플랜 (A안 기준)>
1일차 API 계약·키·테스트 계정 확인, 기존 송장 출력 코드 위치 파악, 호출 규격 정리.
2일차 주소 정제 연동(호출·응답 매핑·저장), 정제 결과 화면.
3일차 분류코드 조회 연동, 주문 건별 저장.
4일차 송장 양식 인쇄(단건·일괄), 예외 목록 화면.
5일차 실제 주소 20건 검증, 오류 수정, 운영 메모 전달.
게이트: 1일차에 API 키를 받지 못하면 그날 작업이 멈춥니다. 키 발급이 늦어지면 일정은 받은 날부터 다시 계산합니다.

<리스크와 대응>
1) 예산과 공수 불일치 — 위 A/B안으로 분리했습니다. B안을 택하시면 "송장에 분류코드가 찍히는 것"은 이번에 되지 않는다는 점을 분명히 해 두고 싶습니다.
2) CJ API 계약·키 부재 — 가장 흔한 중단 원인입니다. 계약이 없거나 대행사를 거쳐야 하면, 대안으로 ① 도로명주소 API로 주소 정제를 대체하고 ② 분류코드는 CJ에 문의해 받은 분류코드 규칙표를 자체 매핑 테이블로 구현하는 방법이 있습니다. 다만 이 경우 코드값이 CJ 기준과 어긋날 수 있어 택배사 확인이 필요합니다.
3) 기존 시스템 접근 — 소스와 서버 접근 권한이 없으면 작업이 시작되지 않습니다. 착수 전에 저장소·서버·DB 접근과 스테이징 환경을 확인합니다.
4) 해외·비정형 주소 — 중국 발송 건의 한국 수취인 주소가 비정형이면 정제 실패율이 올라갑니다. 실패 건을 사람이 처리하는 목록을 기본 포함해, 자동화율을 100%로 약속하지 않습니다.
5) 인쇄 양식 — 프린터·용지(라벨) 환경에 따라 여백이 달라집니다. 실제 라벨 1장을 받아 출력 검증까지 하는 것을 완료 조건으로 둡니다.

<기대 결과>
A안 기준 5일째에 ①관리자 화면에서 주소 입력 시 정제 결과가 뜨고 ②주문 건에 분류코드가 저장되며 ③기존 송장 양식에 그 코드가 인쇄되고 ④정제 실패 건만 따로 모아 사람이 처리할 수 있습니다. B안은 ①까지만 됩니다.

<확인이 필요한 질문>
1. CJ대한통운 택배 API를 직접 계약하셨나요, 물류 대행사를 통해 쓰시나요? 주소 정제·분류코드 API 사용 권한과 테스트 계정이 있나요?
2. 기존 관리자 화면의 기술 스택(언어·프레임워크)과 소스·서버 접근 권한을 받을 수 있나요?
3. A안(1,000,000원)과 B안(200,000원) 중 어느 쪽을 원하시나요? 예산 조정이 가능한 범위도 알려주시면 그에 맞춰 범위를 다시 자르겠습니다.
4. 송장 출력은 단건인가요, 하루 수십~수백 건 일괄인가요? 일괄이면 처리 속도 기준을 정해야 합니다.
5. 사용하는 라벨 용지(규격)와 프린터 방식을 알려주세요. 출력 검증에 필요합니다.

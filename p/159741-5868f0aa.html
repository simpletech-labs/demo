<프로젝트 진단>
지금 상태는 기능이 없는 것이 아니라 구조가 화면 단위로 흩어져 있는 상태로 읽힙니다. Claude Code와 Codex로 화면을 하나씩 만들면 각 화면은 동작하지만, 화면 사이를 잇는 규칙(권한, 상태 전이, 예외)은 아무도 쓰지 않은 채 남습니다. 실제 운영을 막는 지점은 세 곳입니다. 첫째, 권한입니다. 산모가 다른 산모의 계약이나 관리사 연락처를 볼 수 있으면 안 되는데, Supabase에서는 이 규칙이 RLS 정책으로만 강제됩니다. 화면 단위로 생성된 테이블은 정책이 비어 있거나 과하게 열려 있는 경우가 많습니다. 둘째, 결제가 붙는 순간 상태 전이가 서버에서 강제되어야 합니다. 요청→매칭→계약→결제→근무→정산 중 어느 단계에서 결제가 일어나는지, 결제 성공 후 계약 상태를 누가 바꾸는지가 코드에 없으면 환불과 정산에서 바로 분쟁이 납니다. 셋째, 예외입니다. 매칭 취소, 일정 변경, 관리사 노쇼, 부분 환불이 화면마다 다르게 처리되고 있을 가능성이 높습니다.

<작업 범위>
진행할 범위 — ①코드·스키마 진단 리포트(테이블 관계, 중복 필드, RLS 정책 현황, 화면-기능 불일치 목록). ②RLS 정책 재정의와 스키마 정리(역할 3개: 산모·관리사·운영자). ③상태 전이 규칙을 서버에서 강제(결제 성공·취소·환불 웹훅이 계약 상태를 바꾸는 단일 경로). ④예외 시나리오 도출과 처리(취소, 일정 변경, 노쇼, 부분 환불, 관리사 정보 미충족). ⑤PG 연동(카드·간편결제, 웹훅 기반 상태 동기화, 영수증 검증, 취소·부분취소). ⑥디자이너 산출물 반영. ⑦운영 전환(도메인, 백업, 에러 로그, 문의 대응 화면).
제외할 범위 — 신규 기획과 디자인 제작(별도 디자이너 진행분), iOS·안드로이드 앱, 관리사 자격·범죄이력 자동 검증(외부 API 계약 필요), 정산 대행과 에스크로, 마케팅 페이지.
추가 제안 — 에스크로형 정산(결제 대금을 근무 완료 확인 후 지급) 400,000원 / 3일. 계약 테이블에 정산 상태 필드를 지금 넣어 두면 나중에 붙일 때 구조를 다시 만들지 않습니다. 필요하시면 이번 일정에 함께 넣거나 오픈 후에 붙일 수 있습니다.

<실행 플랜>

D7–D9 PG 연동. 테스트 키로 결제·취소·부분취소·웹훅 재전송까지 전 구간 확인.

<리스크와 대응>
첫째, PG 심사입니다. 통신판매업 신고와 사업자 정보가 준비되지 않으면 심사에 1~2주가 걸려 결제 테스트가 막힙니다. 착수 전에 신고 상태와 PG사(토스페이먼츠·포트원 등)를 확인하고, 심사 중에는 테스트 키로 전 구간을 검증해 두었다가 승인 후 운영 키만 교체합니다. 둘째, Supabase 프로젝트 접근 권한입니다. DB 콘솔과 소스 저장소 권한이 없으면 진단 자체가 늦어집니다. 셋째, AI가 생성한 코드를 전면 재작성하는 유혹입니다. 예산과 기간상 재작성은 성립하지 않으므로, 유지하되 위험한 지점(권한·상태·결제)만 걷어내는 방향으로 갑니다. 넷째, RLS 정책 변경 중 데이터 노출입니다. 정책 적용은 스테이징에서 먼저 검증하고 역할별 테스트 계정으로 확인한 뒤 운영에 반영합니다.

<기대 결과>
완료 시점에 산모와 관리사가 가입하고 연결되고 결제까지 끝난 흐름이 실제로 돌아갑니다. 운영자는 결제·취소·환불 내역을 화면에서 확인하고 처리할 수 있고, 누가 어떤 데이터를 볼 수 있는지가 정책으로 남습니다. 코드에는 상태 전이 규칙이 한 곳에 모여 있어, 다음에 기능을 붙일 때 화면마다 다른 처리를 만들지 않아도 됩니다.

<확인이 필요한 질문>
1. 기술 스택은 Next.js와 Supabase를 유지할 것을 권합니다. 지금 구조에서 교체가 성립하는 것은 인증·DB뿐이고, 그마저 옮기는 비용이 이번 예산을 넘습니다. 유지하되 권한·상태·결제 세 곳만 다시 세우는 쪽이 낫습니다.
2. 결제가 일어나는 시점이 언제인가요? 매칭 확정 시 결제인지, 근무 완료 후 결제인지에 따라 상태 전이와 환불 규칙이 달라집니다.
3. PG사를 지정해 두셨는지, 통신판매업 신고는 완료되었는지 알려주세요. 심사 기간이 일정에 직접 영향을 줍니다.
4. 관리사에게 지급되는 수수료 구조(플랫폼 수수료율, 정산 주기)를 알려주세요. 결제만 붙이고 정산이 비어 있으면 운영 첫 달에 손으로 맞춰야 합니다.
5. Supabase 프로젝트와 저장소 접근 권한, 디자이너의 산출물 형식(Figma 여부)과 전달 시점을 알려주세요. 예외 시나리오는 배포된 시연 링크를 직접 눌러보며 뽑겠습니다.

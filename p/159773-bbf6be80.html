<프로젝트 진단>
상담 채팅을 붙이는 일 자체는 어렵지 않습니다. 어려운 것은 붙인 뒤에 상담이 실제로 일이 되게 만드는 부분입니다. 판촉물 주문은 수량·인쇄·납기 조건이 상품마다 달라서, 채팅창만 있으면 상담원이 매번 같은 질문을 다시 하고 답은 카톡과 전화로 흩어집니다. 그러면 채팅은 문의 창구가 아니라 알림창이 됩니다. 그래서 이 프로젝트의 설계 기준은 세 가지로 잡습니다. ①상담이 시작되는 맥락(보고 있던 상품·주문·회원)이 상담 화면에 같이 붙어 있어 상담원이 처음부터 묻지 않게 ②상담 종료 후 대화가 주문·회원 이력에 남아 다음 문의 때 이어지게 ③상담원이 없을 때(야간·동시 문의 폭주) 문의가 사라지지 않고 접수·회신으로 전환. 이 세 가지를 상용 솔루션 기본 기능만으로 맞추려면 결국 별도 작업이 필요해지므로, 상담 데이터를 우리 쪽에 두는 구조로 설계하는 편이 총비용이 낮습니다.

<작업 범위>
진행할 범위 — 요구사항 정의와 상담 흐름 설계, 실시간 채팅(고객·상담원), 상담 배정과 대기열(담당자 지정·다중 상담), 상품·주문·회원 정보 연계, 상담원 화면(대화 목록·이력 검색·상담 메모), 오프라인 문의 접수와 회신, 파일·이미지 전송(시안·견적서), 알림(새 문의·응답 대기), 쇼핑몰 페이지 삽입과 로그인 연동, 관리자 설정(운영 시간·자동 인사·상담원 권한), 상담 통계(응답 시간·건수), 운영 매뉴얼.
제외할 범위 — 쇼핑몰 자체 기능 수정·리뉴얼, 카카오톡 채널·외부 메신저 연동, AI 자동 응답 모델 학습, 결제·주문 처리 로직 변경, 상담원용 네이티브 앱.
추가 제안 — AI 자동 응답(FAQ 기반), 상담 내용 요약, 주문 화면에서 재문의 바로가기, 상담 품질 평가(만족도), 외부 메신저 연동. 지금 함께 진행하거나 오픈 후 확장으로 붙일 수 있습니다.

<리스크와 대응>
가장 먼저 확인할 것은 쇼핑몰 플랫폼입니다. 자체 개발몰이면 데이터 접근이 자유롭고, 외부 SaaS 쇼핑몰이면 제공되는 API 범위 안에서만 연동할 수 있어 상담 화면에 붙일 수 있는 정보가 줄어듭니다. D1–D10에 확인하고, API가 부족하면 채팅 위젯에서 직접 받는 정보(상품 링크·회원 식별값)로 대체하는 경로를 준비합니다. 둘째, 실시간 연결의 안정성입니다. 모바일에서 화면을 껐다 켜거나 네트워크가 바뀌면 연결이 끊기는데, 이때 대화가 사라지면 상담 자체가 무너집니다. 메시지를 서버에 먼저 저장하고 재접속 시 복원하는 순서로 만들며, 동시 접속 부하는 실제 상담 시간대 기준으로 측정해 결과를 문서로 제출합니다. 셋째, 상담원이 없는 시간의 문의입니다. 접수·회신 전환과 알림을 기본으로 넣어 문의가 유실되지 않게 합니다. 넷째, 개인정보입니다. 상담 내용에 연락처·주소가 들어가므로 보관 기간과 열람 권한을 정하고, 파기 절차를 매뉴얼에 넣습니다.

<기대 결과>
완료 시점에 고객은 상품을 보던 자리에서 바로 상담을 시작하고, 상담원은 그 고객이 무엇을 보고 있었는지 확인한 상태로 대화합니다. 상담원이 없을 때 들어온 문의는 접수로 남아 다음 영업일에 회신됩니다. 대화는 주문·회원 이력에 남아 다음 문의 때 다시 묻지 않아도 되고, 응답 시간과 문의 건수는 숫자로 확인됩니다.

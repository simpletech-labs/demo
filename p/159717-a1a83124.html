<프로젝트 진단>
채널이 여러 개로 늘어난 이커머스에서 매출·손익 집계가 어긋나는 원인은 거의 정해져 있습니다. 채널마다 기준일이 다르고(주문일·결제일·배송완료일), 취소·반품이 매출에 섞여 들어가고, 수수료·배송비·광고비가 채널별로 다른 이름으로 들어옵니다. 이 상태에서 대시보드를 먼저 만들면 화면만 예쁘고 숫자는 못 믿는 결과가 됩니다. 그래서 이 과업의 순서는 ① 지표 정의를 문서로 고정 ② BigQuery 적재 구조를 원천·정제·마트 3계층으로 재설계 ③ 그 위에 대시보드를 올리는 것입니다.
84일은 세 단계를 순서대로 하기에 충분하지만, 지표 정의를 2주 안에 확정하지 못하면 ③이 계속 밀립니다. 정의 확정을 첫 승인 게이트로 두었습니다.

<작업 범위>
진행할 범위
1. 지표 정의서 — 매출(총액·순액), 취소·반품, 채널 수수료, 배송비, 광고비, 공헌이익의 계산식을 채널별 원천 컬럼과 함께 표로 확정합니다. 이 문서가 이후 모든 숫자의 기준입니다.
2. 적재 구조 재설계 — raw(원천 그대로) / staging(정제·표준화) / mart(채널·상품·일자 단위 손익) 3계층, 파티션·클러스터링, 증분 적재.
3. 수집 파이프라인 — 채널 API와 정산 파일을 받아 적재하고, 실패·중복·지연을 기록합니다.
4. 정합성 검증 — 주문 원장과 채널 정산 금액의 차이를 자동으로 대사해 차액 목록을 냅니다. 이 검증이 "숫자를 믿을 수 있는가"의 답입니다.
5. 데이터 품질 테스트 — 중복 키, 음수 수량, 미분류 채널, 기간 누락을 매일 점검하고 실패 시 알림.
6. 대시보드 — 채널별 매출·손익 추이, 상품별 공헌이익, 반품률, 광고비 대비 매출, 기간 비교.
7. 이관 — 쿼리·뷰·스케줄 문서화, 담당자 교육 2회, 운영 매뉴얼.

제외할 범위
채널 계정 신규 개설과 API 권한 신청 대행, 회계 시스템 결산 처리, 광고 운영 대행, 원천 ERP 개조.

추가로 제안하는 범위
월 마감 자동화(마감 체크리스트와 잠금 스냅샷)와 손익 예측 화면. 필요하면 지금 함께 진행하거나 V2에서 붙일 수 있습니다.

<리스크와 대응>
가장 먼저 확인할 것은 채널 API 권한과 과거 데이터 소급 범위입니다. 권한이 늦게 나오면 수집 파이프라인 검증이 밀리고, 소급 범위가 12개월을 넘으면 초기 적재 공수가 늘어납니다. 착수 첫 주에 채널 목록·권한 상태·소급 기간을 표로 확정합니다.
두 번째는 기존 테이블입니다. 이미 쓰이는 뷰와 스케줄이 있으면 이름을 바꾸는 순간 다른 리포트가 깨집니다. 기존 객체는 유지하고 새 데이터셋에 병렬로 쌓은 뒤, 숫자가 일치하는 것을 확인하고 전환합니다.
세 번째는 취소·반품의 시점 처리입니다. 주문 시점 기준과 환불 시점 기준이 섞이면 월별 손익이 흔들립니다. 두 기준을 모두 계산해 두고 화면에서 선택하게 합니다.
네 번째는 비용입니다. BigQuery는 스캔량 과금이라 구조를 잘못 잡으면 월 비용이 몇 배가 됩니다. 파티션·클러스터링과 머티리얼라이즈드 뷰로 스캔량을 줄이고, 월 예상 비용을 산정해 알려드립니다.

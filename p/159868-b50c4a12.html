<프로젝트 진단>
지금까지 회사 소개서로만 대응해 왔다는 것은, 이 사이트가 마케팅 페이지가 아니라 대외 영업 도구라는 뜻입니다. 그래서 판단 기준을 두 가지로 잡았습니다. 첫째, 거래처 미팅에서 화면을 띄웠을 때 3분 안에 회사가 설명되는가. 둘째, 개발 담당이 없는 조직에서 오픈 후 문구와 채용 공고를 직접 고칠 수 있는가. 공고에 사내 웹 개발 담당이 없다고 명시되어 있으므로, 관리자 화면을 붙이는 것만으로는 부족합니다. 수정 가능한 범위를 화면 단위로 못 박고 인수인계 문서를 남겨야 실제로 운영이 됩니다.

<작업 범위>
진행합니다. 메뉴 구조(IA)와 화면 설계 6종, PC·모바일 UI 디자인, 로고 1종(가로형·세로형·파비콘 3형), AI 생성 이미지 6컷과 15초 루프 영상 1편, 국문·영문 반응형 웹( Next.js 기반 정적 생성), 관리자 화면(회사소개·프로젝트·채용·계정), 호스팅과 도메인 연결, 관리자 매뉴얼 10쪽입니다.

포함하지 않습니다. 채용 지원의 외부 채용 솔루션 연동(자체 접수 테이블로 구현), 3개국어 이상 확대, 예약·결제, 로고 상표 출원 검토입니다.

추가로 제안합니다. 영문 페이지에 Organization·JobPosting 구조화 데이터를 넣고, 이미지와 영상을 CDN에 두어 국내외 모두 첫 화면 3초 이내 로딩을 목표로 잡습니다. 비개발자가 이해할 수 있도록 기술 선택 이유는 인수인계 문서 2쪽으로 따로 정리해 드립니다.

<리스크와 대응>
가장 먼저 확인할 것은 콘텐츠 확정 시점입니다. 회사 소개서 외에 기획 문서가 없어 문구와 사진이 늦어지면 디자인이 빈 화면 위에서 진행됩니다. D3까지 메뉴별 원고 초안을 저희가 쓰고 클라이언트는 수정만 하시는 방식으로 진행하며, 원고 확정이 D9를 넘기면 해당 섹션만 2차 오픈으로 분리합니다. 두 번째는 영문 문구의 최종 승인 주체입니다. 번역 초안과 원어민 감수 1회는 저희가 맡고 최종 승인은 클라이언트가 하십니다. 세 번째는 AI 생성 이미지의 저작권 범위이며, 사용 범위를 웹 한정으로 할지 인쇄물까지 포함할지 D3에 확정합니다.

기술 스택과 이유입니다. Next.js 15(App Router)와 TypeScript로 만들고, 콘텐츠는 헤드리스 CMS(Sanity 무료 플랜)에 둡니다. 이미지와 영상은 Cloudflare R2에 올려 CDN으로 서빙하고, 배포는 Vercel입니다. 이 조합을 고른 이유는 담당자가 코드를 몰라도 수정할 수 있어야 하기 때문입니다. CMS는 문구·이미지·채용 공고를 정해진 폼으로만 고치게 해서 레이아웃이 깨지지 않습니다. 국문·영문은 하나의 콘텐츠 모델에 언어 필드 2개를 두어, 한 번 입력하면 두 언어 페이지가 같이 갱신됩니다. 빌드 시점에 정적 페이지를 만들어 서버 비용이 거의 들지 않고 첫 화면이 빠릅니다. 별도 서버 관리가 필요 없어 개발자가 없는 조직에 맞는 구성입니다.

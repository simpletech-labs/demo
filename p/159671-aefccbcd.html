<프로젝트 진단>
이 프로젝트의 난이도는 "자동매매"가 아니라 "파동매매기법을 코드가 실행할 수 있는 규칙으로 바꾸는 일"에 있습니다. 파동매매는 사람이 차트를 보며 고점·저점·눌림을 판단하는 기법이라, 그대로 옮기면 규칙이 아니라 감각이 됩니다. 스윙 고점·저점을 어떤 봉 주기에서 몇 개로 볼지, 눌림을 몇 %로 볼지, 진입 후 몇 초 안에 주문이 안 나가면 취소할지를 숫자로 확정해야 하고, 이 확정 작업이 일정의 절반을 차지합니다. 두 번째는 API 제약입니다. 키움 해외선물 API는 신청·승인과 IP 등록, 모의투자 계좌 검증 절차를 거쳐야 하고, 주문 응답이 늦거나 거부될 때의 처리(중복 주문, 부분 체결, 미체결 잔존)를 코드가 견뎌야 합니다. 검증 없이 실계좌에 붙이면 손실이 곧바로 발생하므로, 모의투자 구간을 일정에 못 박는 것이 이 견적의 핵심입니다.

<작업 범위>
포함(1단계)
- 전략 명세화: 파동 정의(봉 주기, 스윙 탐지, 눌림 깊이, 추세 필터), 진입·추가진입·청산·손절 규칙, 파라미터 표 작성. 발주사 구두 설명을 문서로 확정하는 작업 포함.
- 신호 엔진: 실시간 시세 구독, 신호 생성, 백테스트(과거 데이터 리플레이) 및 파라미터 비교 리포트.
- 주문 실행 어댑터: 모의투자 계좌 대상 주문·정정·취소, 주문 상태 추적, 미체결 타임아웃, 중복 주문 차단, API 오류 재시도.
- 리스크 가드: 일 손실 한도, 최대 계약 수, 연속 손실 시 자동 정지, 장 마감 전 강제 청산.
- 운영: 상태 저장 및 재기동 복구(프로그램이 죽어도 포지션을 다시 인식), 전 구간 로그·주문 감사 기록, 알림(텔레그램 등).
- 관제 화면: PC 대시보드(차트·신호·포지션·손익·로그).

제외(2단계, 별도 견적)
- 실계좌 자동 주문 전환, 모바일 웹 관제·원격 제어, 다계좌·다전략 동시 운용, 대외 판매용 라이선스·설치 패키지, 서버 상시 운용 대행.

<실행 플랜>
W1~W2 규칙 확정: 파동 정의·파라미터 표, 키움 API 신청 상태 점검, 데이터 수집기. 산출물: 전략 명세서 v1.
W3~W4 신호 엔진 + 백테스트: 과거 6개월 리플레이, 파라미터 3세트 비교표. 산출물: 백테스트 리포트.
W5~W6 모의투자 연동: 주문 어댑터, 리스크 가드, 재기동 복구, 로그. 산출물: 모의계좌 실주문 로그.
W7~W8 관제 화면 + 모의운영 2주: 대시보드, 알림, 2주 연속 모의운영 결과 정리, 인수 문서.
게이트: W2 명세 확정(여기서 규칙이 안 굳으면 이후 일정 전체가 흔들립니다) → W4 백테스트 승인 → W8 모의운영 2주 결과 승인. 게이트 미통과 시 2단계로 넘기지 않는 것을 원칙으로 합니다.

<리스크와 대응>
1) 파동 로직이 문서로 없다 — 가장 큰 변수입니다. W1에 발주사 설명을 녹취·문서화해 "숫자로 된 규칙표"로 만들고, 발주사 확인 서명을 받은 뒤 개발에 들어갑니다. 규칙이 개발 중 바뀌면 파라미터만 바꾸도록 엔진과 규칙을 분리해 설계합니다.
2) 실거래 손실 책임 — 프로그램은 규칙을 실행할 뿐 투자 판단의 주체가 아닙니다. 손실 한도·최대 계약 수를 코드에 강제하고, 1단계는 모의계좌만 사용합니다. 실계좌 전환은 2주 모의운영 결과를 보고 발주사가 결정합니다.
3) API 승인·IP 등록 지연 — 키움 API는 승인과 IP 등록에 시간이 걸립니다. 착수 즉시 신청 서류를 확인하고, 승인 전에는 과거 데이터 리플레이로 개발을 진행해 일정을 잃지 않게 합니다.
4) 프로그램 중단 시 포지션 방치 — 주문·포지션 상태를 파일/DB에 남기고 재기동 시 대조·복구하는 절차를 넣습니다. PC 전원이 꺼지는 상황은 1단계에서 탐지·알림까지만 하고, 상시 운용은 2단계 서버 구성에서 다룹니다.
5) 장중 급변 시 신호 폭주 — 동일 방향 중복 진입 차단과 초당 주문 상한을 두고, 초과 시 정지 후 알림합니다.

<기대 결과>
60일째에 ①발주사의 파동 기법이 숫자 규칙표로 문서화되고 ②그 규칙으로 과거 6개월 백테스트 결과가 나오며 ③모의계좌에서 2주간 사람 개입 없이 진입·청산이 반복된 로그가 남고 ④프로그램을 재시작해도 포지션을 잃지 않습니다. 실계좌 전환 여부는 이 네 가지를 보고 판단하실 수 있습니다.

<확인이 필요한 질문>
1. 파동매매 규칙을 정리한 문서가 있나요? 없다면 통화 2시간으로 규칙을 뽑아내는 작업을 첫 주에 잡겠습니다.
2. 키움 해외선물 API 신청·승인은 완료되었나요? 모의투자 계좌도 함께 발급되어 있나요?
3. 대상 종목은 나스닥100 선물 중 어느 계약인가요? (MNQ/NQ 등) 거래 주기와 1회 진입 계약 수는 어떻게 되나요?
4. 일 손실 한도와 최대 동시 포지션 수를 정해 주실 수 있나요? 정하지 않으시면 보수적 기본값으로 넣고 파라미터로 열어 두겠습니다.
5. 모바일 웹 제어를 1단계에 꼭 넣어야 하나요? 넣으면 관제 화면 작업이 2주 늘어 60일 안에서 백테스트·모의운영 기간을 줄여야 합니다.

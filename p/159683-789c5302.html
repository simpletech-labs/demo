<프로젝트 진단>
기획은 이미 끝나 있고 실행 환경이 막힌 상태입니다. 공고에 적힌 증상이 이를 그대로 보여줍니다. 1차 시제품은 있으나 새 파일 생성 권한이 막혀 일부 화면이 누락됐고, 운영자 어드민 13개 메뉴는 실제 화면이 아니라 안내 문구로만 들어가 있습니다. 즉 이번 7일의 난이도는 기능 설계가 아니라 ①9개 역할과 13개 메뉴를 한 번에 화면으로 세우는 일 ②역할을 바꿔 클릭할 때 승인·잠금 상태가 앞뒤로 맞는 일입니다. 지원자가 199명인 공고이므로 차이는 금액 10만원이 아니라 11.28에 무엇이 남아 있는지로 갈린다고 봅니다. 화면 수는 기획서 기준으로 9개 역할 업무 화면과 어드민 13개 메뉴, 공개 4개 페이지입니다.

<작업 범위>
진행할 범위 — ①공개 영역: 메인(핵심 메시지·3대 원칙·신뢰 지표), 서비스 소개(기관용·직원용 분리), 도입 문의 폼, 개인정보 처리 안내. ②역할 전환 시연: 9개 역할(발령자·사택담당자·인사담당자·결재권자·공인중개사·관리사무소·임대인·사택온 운영자·감사자) 선택 로그인, 타 역할 주소 접근 시 권한 안내. ③역할별 업무 화면: 발령 등록·공실 확인·주거 요청서·후보 물건 제출·입주 신청·계약 기록·매월 비용·수리 요청·반납·재고. ④핵심 시연 규칙: 월세가 직급 한도 이내면 자동 승인, 초과 시 결재권자 승인 전까지 계약 기록 잠금. ⑤어드민 13개 메뉴를 실제 표·필터·상세가 있는 화면으로 구축(부임일 14일 이내 지연 위험 표시, 계약 6가지 지급 요건 체크, 실비 중복 의심 표시 포함). ⑥민감정보 마스킹: 역할에 따라 등기부등본 원본과 요약본을 구분 표시하고 임대인 계좌 가운데 자리 가림. ⑦배포와 404 안내.
기술 스택 — Next.js 15 App Router + TypeScript + Tailwind CSS로 화면을 만들고, 데이터는 기획서의 18개 데이터 구조를 그대로 옮긴 정적 JSON과 브라우저 저장소(localStorage)로 처리합니다. 서버·DB가 없어도 새로고침 후 승인·잠금 상태가 유지되고, 역할을 바꿔도 같은 데이터를 봅니다. 배포는 Vercel, 저장소는 발주사 명의로 넘깁니다. AI 도구는 Claude Code를 쓰고, 화면 1개 단위로 생성→화면 확인→수정 순서로 진행합니다. 이 조합을 고른 이유는 서버 없이도 상태가 일관되고, 나중에 실제 API를 붙일 때 페이지 구조를 다시 만들지 않아도 되기 때문입니다.
제외할 범위 — 실제 백엔드 서버·DB·인증 서버, 외부 유료 API 실연동(등기부등본·세금계산서·이체·알림톡은 화면과 상태 변경으로만), 모바일 앱, 기획서에 없는 신규 기능, 기존 시제품 코드의 구조 유지.

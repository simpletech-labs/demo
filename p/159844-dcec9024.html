유사 프로젝트를 외주로 수행한 실적은 없습니다. 대신 직장에서 거래·정산·관리자 도구를 직접 만들어 운영한 경험으로 답합니다. ①온라인 경매에서 응찰이 몰릴 때 Redis·Celery로 비동기 큐잉하고 트랜잭션으로 정합성을 잡았습니다. 응찰·낙찰·결제·배송 상태가 한 흐름으로 이어지는 구조라, 카운터 오퍼의 제안·수락·만료 상태 관리에 같은 설계를 씁니다. ②갤러리 상품을 옥션에서 판매하는 마켓플레이스와 Admin 사이트를 기획부터 개발까지 맡았고, 쿠폰 발급·적용과 주문·배송 조회 화면을 개발했습니다. ③올더게이트 결제모듈 연동과 결제·취소·환불 처리, Spring Scheduler 기반 월별 미수금 자동 생성·정산을 운영했습니다. ④얼라인업에서 고객사별 워크스페이스 분리(멀티테넌시)와 권한 제어를 설계해, 국내·해외 리전을 같은 코드로 나눠 운영하는 구조에 적용할 수 있습니다. TCG 도메인은 새로 익혀야 하지만, 이 공고의 난점은 카드 지식보다 망분리와 대금 보관의 정합성 문제입니다.

<프로젝트 진단>
이 공고는 앱 2종·웹·서버 2벌을 120일에 만드는 일보다, 세 가지가 겹치는 지점에서 어려워집니다. 첫째, 망분리는 서버를 두 벌 놓는 일이 아니라 거래가 국경을 넘는 순간의 문제입니다. 구매자와 판매자의 리전이 다르면 결제 통화·정산 통화가 다르고, 개인정보보호법 제28조의8에 따라 회원·거래 데이터의 보관 위치와 국외 이전 동의를 거래 단위로 관리해야 합니다. 둘째, 카운터 오퍼가 특허 출원 중이고 NDA 전이라 요구사항이 확정되지 않았습니다. 화면에 직접 박으면 규칙이 바뀔 때마다 재작업이 생기므로, 협상 상태를 데이터 모델로 분리하고 규칙만 갈아끼우는 구조가 필요합니다. 셋째, 기획이 아이디어 단계이고 발주사에 PM이 없으며 정부지원사업입니다. 정의서·설계서를 우리가 쓰고, 그 산출물이 지원사업 일정과 맞물립니다.

<작업 범위>
진행: ①요구사항·화면 설계서 작성과 확정 ② iOS·Android 앱(웹 자산을 공유하는 하이브리드, 카메라·푸시·결제만 네이티브 브리지)과 반응형 웹 ③국내·해외 리전 분리 구축과 배포 파이프라인(GitHub Actions, Docker, 리전별 환경 분리) ④카드 마스터(게임·세트·카드번호·언어판·레어도)와 매물(상태 등급·사진·가격) 구조 ⑤검색·필터·시세 참고 표시 ⑥ 1:1 채팅(거래 단위 방, 읽음·알림, 신고·증빙 첨부) ⑦카운터 오퍼 ⑧ PG 결제와 에스크로(보관·수령 확인·정산) ⑨ Admin(회원·매물 심사, 신고, 분쟁 중재, 정산 보류·재지급, 수수료 설정) ⑩앱 마켓 등록·출시 ⑪베타 운영 대응과 배포·운영 매뉴얼.
제외: 실물 감정·검수 대행, 물류 계약과 배송 대행, 관세 대납, 위조 판별 모델 학습, 법률·특허 자문, 결제대금예치업 직접 등록, 시세 예측.
추가 제안: 판매자 리뷰, 위시리스트와 가격 알림, 2개 언어 표시. 2차로 붙일 수 있습니다.

<리스크와 대응>
1) 카운터 오퍼 요구가 늦게 확정될 경우 — 협상 상태를 별도 테이블과 상태 전이로 구현하고, 규칙(횟수 제한·만료·자동 수락)은 설정값으로 뺍니다. NDA 전에는 목업으로 흐름만 합의합니다.
2) 리전 간 데이터 정합성 — 회원·거래의 원장 리전을 거래별로 하나만 두고, 상대 리전은 서명된 내부 API로만 조회합니다. 양쪽에 같은 데이터를 복제하지 않습니다.
3) 에스크로의 법적 성격 — 대금을 직접 보관하면 전자금융거래법상 예치업 등록 문제가 생기므로, PG 에스크로·지연 정산을 쓰고 정산 주기와 보류 사유는 Admin에서 관리합니다.
4) 앱 심사 반려 — 계정 삭제, 인앱결제 정책, 개인정보 처리방침이 주요 반려 사유입니다. D81에 제출해 반려 시 수정 기간을 확보합니다.
5) 지원사업 산출물 일정 — 정의서·설계서를 개발과 병행해 매 게이트마다 제출본을 확정합니다.

<기대 결과>
성공 기준: ①국내 사용자가 매물 등록→채팅→카운터 오퍼→결제→수령 확인→정산을 앱과 웹에서 끝까지 완료한다 ②해외 사용자와의 거래가 같은 흐름으로 성립하고, 데이터 보관 위치와 국외 이전 동의가 거래별로 기록된다 ③두 리전이 같은 기능을 제공하며 한쪽 장애가 다른 쪽 거래를 멈추지 않는다 ④분쟁이 증빙과 처리 이력으로 Admin에 남고, 정산 보류·재지급이 화면에서 처리된다 ⑤iOS·Android 앱이 마켓에 출시된 상태다 ⑥정의서·설계서·DB 스키마·소스코드·운영 매뉴얼이 발주사 저장소에 인계된다. 여기까지를 1차 출시 완료로 봅니다.

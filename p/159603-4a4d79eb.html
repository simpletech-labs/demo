<프로젝트 진단>
이 공고에서 비용이 새는 지점은 화면이 아니라 데이터입니다. 납본·회원 데이터가 여러 해 쌓여 중복·오류가 섞여 있고 "무엇이 정상인지" 기준이 없습니다. 기준 없이 이관하면 건수 대조 단계에서 차이가 나고, 그때부터 원인 찾기가 시작됩니다. 그래서 착수 첫 주에 "정리 기준표"(중복 판정, 필수값, 인코딩, 첨부 경로 규칙)를 먼저 만들고 발주사 확인을 받습니다. 두 번째는 워드프레스·PHP 버전 최신화입니다. 게시판(KBoard)과 회원 기능이 플러그인과 커스텀 코드로 얽혀 있어 버전만 올리면 기존 화면이 어긋납니다. 회귀 검증 범위를 계약 시점에 못 박아야 예산이 유지됩니다. 세 번째는 개인정보입니다. 2023년 유효기간제 폐지로 보관 기간을 사업자가 정해 밝혀야 하므로, 암호화·가림·분리 보관·파기 기준서를 결과물에 포함했습니다.

<기술 스택과 이유>
기존 워드프레스의 자식 테마를 새로 만들어 디자인을 얹고, PHP는 8.2 계열로 올리는 방식을 권합니다. 이유는 세 가지입니다. ① 담당자가 지금 쓰는 관리자 화면을 그대로 쓸 수 있습니다(새 도구를 배우지 않아도 됩니다). ② 기존 회원 계정과 게시판 데이터를 옮기지 않아 로그인·비밀글이 깨지지 않습니다. ③ 기존 주소를 그대로 살릴 수 있습니다. Headless(React) 방식은 화면 자유도가 높지만 콘텐츠 수정 때마다 개발자가 필요해지고, 사내에 개발자가 없다는 조건과 맞지 않습니다.

<미정 범위 3건 — 의견과 별도 견적>
1) 화면 구성 방식: 이번 범위는 기존 테마 개편을 권합니다. Headless 전환은 별도 견적 6,500,000원/20일입니다. 다만 공통 컴포넌트를 CSS 변수 기반으로 만들어 두면 나중에 자산을 그대로 씁니다.
2) 서버 이전: 이전을 권합니다. PHP 8.2와 최신 워드프레스는 노후 서버에서 보안 패치가 막히는 경우가 많습니다. 별도 견적 1,800,000원/7일, 월 서버비 25~35만원(사양에 따라). 이전 없이 진행해도 개발은 가능합니다.
3) 회원 서브사이트 디자인 적용: 1차에서는 메인 사이트만 하고, 서브사이트는 같은 컴포넌트로 2차에 확장하는 편을 권합니다. 별도 견적 3,200,000원/10일. 1차에 넣으면 45일 안에 데이터 이관 검증 시간이 줄어듭니다.

<실행 플랜>
1~2주 현행 조사·데이터 기준표·IA·화면 정의서 (게이트: 기준표 승인)
3~4주 디자인 시안 → 확정, 공통 컴포넌트
5~6주 테마 개발·PHP 최신화·게시판·회원 정비 (게이트: 스테이징 오픈)
7주 데이터 정리·이관, 건수 대조 보고서
8주 회귀 테스트·SEO·매뉴얼·운영 이관

<진행 확인 방법>
매주 금요일 1장 보고서(이번 주 완료·다음 주 예정·이슈·결정 필요 사항)를 보내고, 스테이징 주소를 3주차부터 상시 열어 두어 담당자가 직접 화면을 확인하실 수 있게 합니다. 이슈는 공유 보드에 남겨 "무엇이 왜 밀렸는지"가 남게 합니다.

<리스크와 대응>
1) 데이터 정리 범위 폭발 — 가장 큰 위험입니다. 1주차에 정리 기준표와 함께 "이번에 정리할 건수"를 확정하고, 초과분은 별도 견적으로 분리합니다. 기준 없이 시작하면 7주차에 일정이 무너집니다.
2) 플러그인 회귀 결함 — 업그레이드 전 스테이징에서 전 페이지·게시판·회원 기능을 목록화해 하나씩 확인하고, 문제 플러그인은 대체·제거 목록으로 보고합니다.
3) 개인정보 파기 기준 미확정 — 기준서 초안을 2주차에 드리고 승인 후 적용합니다. 승인이 늦으면 해당 기능만 오픈 후 적용으로 넘깁니다.
4) 기존 업체에서 자료·권한 인수 지연 — 착수 전에 서버·DB·도메인·계정 인수 목록을 문서로 주고받습니다. 늦어지면 일정이 같은 일수만큼 밀립니다.

① 휴대폰에서 60여 페이지가 다시 디자인되지 않고 읽힌다. ② 담당자가 지금 쓰는 관리자 화면에서 글 게시·회원 관리를 그대로 한다. ③ 이관 전후 건수 대조표의 차이가 0이거나 이유가 적혀 있다. ④ 개인정보 보관·파기 기준서가 문서로 남는다.

<프로젝트 진단>
공고에서 일정과 결과물을 좌우하는 조건은 세 가지입니다. 학습 데이터 약 2만 건이 이미 있고 환자 정보·진단명 형태로 라벨이 붙어 있다는 점, 결과를 사람이 확인하는 웹 인터페이스와 관리자 페이지가 별도로 필요하다는 점, 최종 목표가 초음파 기기 탑재라는 점입니다. 앞의 둘은 90일 안에 끝낼 수 있는 소프트웨어 작업이지만 세 번째는 기기 제조사 SDK·연산 자원·의료기기 인증이 걸린 별도 트랙입니다. 이번 견적은 앞의 둘을 확실히 끝내고, 세 번째를 바로 이어받을 수 있는 형태(추론 API 분리, 모델 경량화, 오프라인 추론 패키징)로 넘겨드리는 데 맞췄습니다.
2만 건을 그대로 학습에 넣는 것도 위험합니다. 같은 환자의 프레임이 학습셋과 검증셋에 나뉘어 들어가면 정확도가 실제보다 높게 나옵니다. 환자 단위로 나누는 분할을 첫 주에 확정합니다.

<작업 범위>
진행할 범위
1. 데이터 감사 — 2만 건의 클래스 분포, 중복·저품질 프레임, 라벨 누락을 표로 정리하고 학습 가능 건수를 확정합니다.
2. 전처리·라벨 파이프라인 — 원본 형식 정규화, 환자 단위 분할, 클래스 불균형 보정 규칙.
3. 모델 학습·검증 — 분류 모델, 환자 단위 교차검증, Grad-CAM으로 판단 근거 시각화.
4. 추론 API — FastAPI 기반, 건당 판독 요청·결과 조회·버전 지정.
5. 판독 웹 화면 — 영상, 판독 후보, 신뢰도, 근거 히트맵을 한 화면에.
6. 관리자 — 데이터 업로드, 모델 버전 관리, 판독 이력, 계정·권한.
7. 서버·DB 구축과 Docker 기반 배포, 성능 리포트.

제외할 범위
의료기기 인증(SaMD) 대응 문서, 기기 펌웨어·드라이버 연동, 병원 PACS 연동, 모바일 앱.

추가로 제안하는 범위

<리스크와 대응>
가장 먼저 확인할 것은 데이터 사용 권한과 라벨 품질입니다. 학습에 쓸 수 있는 건수와 진단명이 확정된 건수가 확인되기 전에는 정확도 목표를 약속하지 않습니다. 확인 즉시 감사 결과표로 학습 가능 건수와 예상 지표 구간을 제시합니다.
두 번째는 클래스 불균형입니다. 특정 질환이 수십 건 수준이면 증강·전이학습으로 대응하고, 해당 클래스는 화면에 "검토 보조"로 표기해 과신을 막습니다.
세 번째는 개인정보입니다. 영상에서 환자 식별정보를 분리 저장하고, 접근 로그·권한을 남기며, 저장 리전을 국내로 고정합니다. 초음파 기기 탑재는 제조사 런타임 제약을 받으므로 지원 가능한 모델 형식과 연산 예산을 미팅에서 확인합니다.

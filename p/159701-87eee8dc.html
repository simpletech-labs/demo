<프로젝트 진단>
이 과제의 병목은 화면이 아니라 맛 모델입니다. 지금 가진 데이터는 제품명·형태·맵기 수치·식단 여부까지이고, 20개 제품을 취향 축으로 비교할 속성과 점수 기준이 없습니다. 추천 엔진은 그 위에만 성립하므로 1단계를 "속성 정의→점수 산정→전체 조합 시뮬레이션"으로 고정하고, 이 검증을 통과한 뒤 개발에 들어가는 순서가 맞습니다. 두 번째 목표인 익명 선호도 수집은 추적 도구 없이 세션 단위 이벤트만 쌓는 구조로 설계하면 GDPR 쿠키 배너 없이도 성립합니다. 기술 스택은 Next.js(App Router) + TypeScript + PostgreSQL, 배포는 EU 리전(Frankfurt) 컨테이너 + 관리형 DB로 제안합니다. 기존 사이트가 Next.js·MongoDB·Vercel이므로 팀이 읽기 쉬운 스택이 유지보수에 유리하고, EU 호스팅 요구는 Vercel EU 리전 대신 EU 리전 컨테이너로 두어 데이터 저장 위치를 명확히 합니다.

<작업 범위>
진행할 범위 (1단계)
1) 리서치·맛 모델: 맛 속성 8~10개 정의, 20개 제품 점수 산정, 한국어 검토 엑셀, 전체 답변 조합 시뮬레이션 결과 보고(추천되지 않는 제품·독점 제품 목록 포함).
2) 디자인: 모바일 우선 퀴즈 6화면(시작·질문·식단·계산·결과·조리법), 360×640에서 스크롤 없는 한 화면, 결과 공개 애니메이션, Figma 원본.
3) 개발: 퀴즈 웹(비로그인), 가중치 매칭 엔진, 필터·우선순위·역할 배정(베스트/클래식/새로운 맛), 관리자 웹(제품·맛 항목·질문·조리법·점수 설정·행사·시뮬레이션), 익명 이벤트 수집과 행사별 분석·CSV.
4) 인프라: EU 리전 배포, 전용 도메인·HTTPS, DB 자동 백업, 자동 재시작, 명령어 1회 재배포.
5) 인수: 브라우저 검수(iOS Safari·Android Chrome 최신 2버전·데스크톱), 관리자 가이드, 인수인계 미팅 1회.

제외할 범위
- 자사 웹사이트 삽입·제품 API 연동(별도 견적), 결제·회원 기능.
- 6개 언어 전체 번역(1단계는 영어·독일어, 나머지는 구조만 준비), 한국어 관리자 페이지.
- 행사 현장 장비·네트워크, 제품 사진 촬영.

별도 견적 (1단계와 분리)

- 2단계(5개 언어 추가·한국어 관리자·다중 관리자 권한·통합 대시보드): 22,000,000원 / 45일.

<실행 플랜>
1단계 R1~R3 (12.01~12.19) 맛 속성 정의·점수 산정·시뮬레이션 → 1차 승인 게이트.
2단계 D1~D15 (12.22~01.09) 디자인 6화면·디자인 시스템 → 2차 게이트.
3단계 개발 (01.12~02.12) 퀴즈·엔진·관리자·분석, 주 1회 리뷰.
4단계 런칭 (02.15~02.26) EU 배포·검수·인수인계.
총 공수 62일 / 90일 중 버퍼 28일(콘텐츠·번역 지연 대응). 투입은 백엔드 1명 상시 + 프론트·디자인 1명 단계별 투입입니다.
온라인 협업: 한국 시간 오후 3~6시가 네덜란드 오전 8~11시와 겹칩니다. 주간 리뷰는 이 구간에 고정하고, 이슈는 위시켓 메시지 + 주 1회 화상, 긴급 건은 24시간 내 회신을 기준으로 합니다. 모든 산출물은 문서(Notion 또는 공유 문서)로 남겨 시차 중 비동기 확인이 가능하게 합니다.

<리스크와 대응>
1) 맛 모델 승인이 늦으면 전체가 밀립니다. R1~R3에 시뮬레이션 결과를 먼저 보여드리고, 속성 정의는 2회 수정까지 포함해 확정합니다.
2) 콘텐츠(제품별 조리법·다국어 문구·사진) 제공이 늦는 경우. 문구가 비어 있어도 화면이 깨지지 않도록 기본 문구·플레이스홀더를 넣고, 콘텐츠는 관리자에서 나중에 채우는 구조로 만듭니다.
3) EU 호스팅·데이터 위치 요구. 컨테이너와 DB 리전을 EU로 고정하고 데이터 이동 경로를 문서화합니다. 개인정보를 수집하지 않으므로 별도 동의 절차는 두지 않습니다.
4) 행사당 최대 2만 명 접속. 정적 자산 CDN 분리와 API 응답 캐시로 대응하고, 행사 전 부하 점검 절차를 런칭 단계에 포함합니다. 실측 수치는 배포 후 리포트로 제출합니다.

<기대 결과>
완료 시점에 마케팅팀은 개발자 없이 제품 20개·질문·행사를 관리자에서 직접 관리하고, 행사별로 전용 링크와 QR을 만들어 운영합니다. 방문객은 20초 안에 자신에게 맞는 제품과 대안 2개를 받고 조리법까지 이어서 봅니다. 경영 측면에서는 행사·국가별 입맛 선호도가 익명 데이터로 축적되어 다음 제품 기획의 근거가 됩니다. 성공 기준은 ①추천되지 않는 제품 0건(시뮬레이션 검증) ②행사 링크 생성 후 10분 내 운영 가능 ③퀴즈 완료율과 평균 소요 시간이 관리자 화면에서 즉시 확인됨 ④개발자 개입 없이 제품·질문 변경 가능 — 네 가지로 제안합니다.
